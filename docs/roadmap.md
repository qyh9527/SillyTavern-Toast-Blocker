## 对旧路线图的修正

### 1. 原生启动通知不能直接承诺完整后台计时接管

插件激活前已创建的原生通知，其计时器和回调状态存在 Toastr 内部闭包。移动 DOM 并不能取得剩余时间，更不能取消闭包内的定时器。如果另外加一个插件定时器，会造成双重计时、提前删除或重复回调。

当前实现保留原节点与交互，管理数量、句柄与清理；新重绘通知继续支持后台计时冻结，启动接管通知保留宿主计时。这是明确的兼容边界，不属于“已经完整接管”。

只有宿主提供明确的取消/剩余时长接口，或者有可靠的创建前拦截协议，才考虑进一步实现。不要通过克隆 HTML 丢弃原节点事件来假装解决问题。

### 2. getContext 并不保证有立即保存接口

官方推荐 context 作为更稳定的入口，但它可能只暴露 saveSettingsDebounced。刷新前必须等待真正的持久化完成，因此保留对 /script.js 中 saveSettings 的动态回退。自检显示 mixed 是正常兼容模式。[SillyTavern 扩展文档](https://docs.sillytavern.app/for-contributors/writing-extensions/)

### 3. 浏览器测试与 WebView 真机验收分别记录

Playwright 可以在多个浏览器和设备模拟项目中运行同一套测试，但模拟移动视口不能验证 TT 容器的暂停/恢复、剪贴板授权或系统 WebView 差异。[Playwright 项目配置](https://playwright.dev/docs/test-projects)

本轮 E2E 使用最小宿主接口夹具及真实 jQuery/Toastr，不是完整 ST 或 TT。不能把“已写测试配置”写成“已通过全平台验证”。

## 建议版本安排

v1.4.3 已通过工作流与面板自动化验收；此前 v1.4.2 的 40 项浏览器测试使用旧 CSS，不能作为后续状态头改动的验收结论。下一步请用户在真实宿主确认折叠交互与诊断展示；浏览器夹具不等同于设备回测。

### v1.4.2：已完成折叠概览与节流（历史）

折叠设计、面板合并与长帧冷却节流见顶部一节。修复 Windows 本地 E2E 服务器 403 缺陷，本地 E2E 从“完全无法运行”恢复到 40/40。

### v1.4.4 建议：空闲开销与异常恢复

建议组合“启动整树监听超时”“面板延迟挂载重试”两个方向。诊断观察器重连语义已在 v1.4.1 处理，长帧刷新节流已在 v1.4.2 处理。它们都服务于减少长期运行的无效工作，并补齐宿主加载慢或反复启停时的行为。

验收至少包括：从没有通知的长聊天中确认没有常驻整树回调；超时后首次通知仍按规则隐藏；设置区晚于 5 秒出现时仍可恢复挂载；插件停用后没有新增定时任务。

### 后续按实际反馈决定

- 可选 HTML 安全模式：如确有用户需要，再研究宿主 DOMPurify 的可用性；不要在小版本中强制改变富文本语义。
- 少量预设：仅在反复出现配置误解时考虑“静音/只留错误/全部重绘/原生”，目前面板已经有全选与全取消。
- 英文翻译：有明确海外使用需求时再做。

## 暂不建议

通知历史中心、关键词屏蔽、云端统计、依赖调用栈猜来源、复杂手势/物理动画、用 Worker 操作 DOM。它们会增加维护与交互成本，目前缺少足够的用户收益证据。

不要追求隔离一切宿主样式而直接改成 iframe：设置挂载、字体主题、键盘焦点和弹层层级都需要重新处理。当前继续使用面板作用域和明确的样式降级；有具体冲突样例后再评估 Shadow DOM。

## 回归用例建议

每个新问题应保留“宿主/系统版本、触发操作、预期、实际、自检报告”五项信息。报告默认不含正文；如需分享截图，用户自行选择。不要默认收集通知内容、聊天或完整配置。

优先补真实用户能触发的回归，避免写大量只验证代码字符串存在的测试。当前 CSS 源码断言继续保留，但跨引擎视觉和交互用例才是判断开关、布局是否实际正常的依据。
